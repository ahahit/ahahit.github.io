## 요약

공부하다 보면 분명 조금 전까지 이해했던 내용인데, 며칠 지나면 다시 검색하게 된다. 그래서 배운 내용과 직접 해본 과정을 모아두는 블로그를 시작하기로 했다.

아직 이 분야의 초심자다. 잘 정리된 결과뿐 아니라 **어디에서 막혔고, 무엇을 바꿨으며, 결국 어떻게 해결했는지**까지 남겨보려고 한다. 이 블로그의 첫 번째 실습은 블로그 자체를 만드는 일이 됐다.

| 항목 | 내용 |
| --- | --- |
| 블로그 이름 | 알쏭달쏭 디지털세계 |
| 오늘의 목표 | 공부 기록을 올릴 공간 만들기 |
| 사용한 도구 | GitHub Pages, MkDocs, Material for MkDocs |
| 첫 번째 성과 | 블로그 게시와 첫 글 작성 |
| 현재 상태 | 모르는 게 많지만 하나씩 해보는 중 |

!!! note "이 블로그의 기준"

    완벽하게 이해한 다음에만 쓰려고 하면 첫 글을 영영 못 쓸 것 같다.
    일단 지금 이해한 만큼 적고, 직접 확인한 내용과 아직 궁금한 부분을 구분해서 남기기로 했다.

## 블로그를 만들면서 한 일

### 1. 내 주소부터 정하기

GitHub 아이디를 `ahahit`으로 바꾸고, `ahahit.github.io`라는 저장소를 만들었다. 이름 하나 정하는 일인데도 앞으로 계속 사용할 주소라고 생각하니 은근히 신경이 쓰였다.

블로그 이름은 **알쏭달쏭 디지털세계**. 아직 알쏭달쏭한 게 많으니 지금의 나와 잘 어울린다.

### 2. 마음에 드는 블로그 모양 찾아보기

처음에는 Chirpy 테마로 시작했다. 그런데 참고한 블로그처럼 만들고 싶어서 다시 살펴보니, 그쪽은 Material for MkDocs를 사용하고 있었다.

덕분에 비슷한 블로그처럼 보여도 사용하는 도구와 설정 방법은 다를 수 있다는 걸 배웠다. 지금은 같은 테마를 바탕으로 글 목록, 썸네일, 본문 스타일을 조금씩 맞추는 중이다.

### 3. 글과 디자인의 역할 나누기

처음에는 파일들이 전부 비슷해 보였다. 지금은 우선 이 정도로 구분하고 있다.

| 파일 또는 폴더 | 하는 일 |
| --- | --- |
| `mkdocs.yml` | 사이트 이름, 메뉴, 테마 같은 전체 설정 |
| `docs/posts/` | 내가 작성한 공부 글 |
| `docs/stylesheets/extra.css` | 글 목록과 공통 디자인 |
| `docs/stylesheets/article.css` | 본문의 글자 크기와 세부 스타일 |
| `.github/workflows/pages-deploy.yml` | 저장한 내용을 사이트로 만들어 게시하는 작업 |

```text
글 또는 설정 수정
  -> GitHub에 저장
  -> Actions에서 사이트 생성과 게시
  -> 블로그에서 결과 확인
```

## 오늘의 우당탕탕 기록

### 파일 이름을 본문에 적었다

새 글을 만들면서 파일 경로를 본문 첫 줄에 붙여넣었다. 파일 이름을 적는 칸과 글 내용을 적는 칸은 따로 있었다. 지금 보면 단순하지만 처음에는 이런 부분부터 헷갈렸다.

앞으로는 저장하기 전에 **파일 위치, 맨 위 설정 영역, 본문 시작 위치**를 확인해야겠다.

### 저장했는데 화면은 그대로였다

분명 제목과 디자인을 바꿨는데 블로그에는 예전 모습이 계속 나왔다. 다른 창에서 확인했더니 새 제목이 보여서 더 헷갈렸다.

이번에는 브라우저에 남은 이전 화면이 문제였다. 이제는 무작정 파일을 다시 수정하기 전에, 게시 작업이 끝났는지와 이전 화면을 보고 있는지를 먼저 확인해보기로 했다.

!!! warning "바로 안 바뀐다고 같은 코드를 또 붙이지 않기"

    먼저 GitHub Actions의 게시 상태를 확인한다.
    게시가 끝났다면 캐시를 사용하지 않는 환경에서 화면을 다시 확인한다.
    화면이 그대로라는 이유만으로 설정을 중복해서 추가하지 않도록 주의하자.

### 썸네일이 본문만큼 크게 나왔다

원한 것은 작은 이미지가 왼쪽에 있는 글 카드였는데, 처음에는 병아리 이미지가 카드 대부분을 차지했다.

이미지 파일을 올리는 것과 목록에서 어떻게 배치할지는 별개의 일이었다. 글에 썸네일 표시를 붙이고 CSS에서 크기와 위치를 정하면서 조금씩 원하는 모습에 가까워졌다.

## 앞으로 글을 쓰는 방식

글마다 아래 흐름을 기준으로 정리해보려고 한다.

1. **요약:** 무엇을 공부했고 무엇을 알게 됐는지 먼저 적기.
2. **개념:** 새로 나온 용어를 내 말로 설명하기.
3. **실습:** 실행한 코드와 확인한 결과 남기기.
4. **시행착오:** 오류 메시지, 시도한 방법, 해결 과정 기록하기.
5. **정리:** 아직 모르는 점과 다음에 해볼 일 적기.
6. **참고 자료:** 다시 찾아볼 수 있도록 출처 남기기.

글 안에서 명령어나 파일 이름은 `이런 모양`으로, 가장 중요한 문장은 **굵게** 표시할 생각이다. 코드는 본문과 구분해서 적는다.

```python
# 앞으로 실습 기록을 남길 때 사용할 간단한 코드 예시
topics = ["오늘 배운 것", "막혔던 부분", "다음에 해볼 것"]

for topic in topics:
    print(topic)
```

!!! tip "미래의 나에게 설명하기"

    나중에 다시 읽었을 때 왜 이렇게 했는지 알 수 있게 쓰자.
    정답만 적기보다, 그 정답까지 가는 과정도 한 줄 더 남겨보자.
